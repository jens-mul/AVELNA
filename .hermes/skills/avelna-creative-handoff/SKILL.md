# AVELNA Creative Handoff (project-local)

On an AVELNA creative execution task, read `AGENTS.md`, `docs/creative.md` and the relevant one of `docs/creative-system/` manuals first.

1. The **founders and ChatGPT create all images and creative prompts**. Hermes only consumes the exact approved artifact and is not another art director.
2. Reuse existing personal *official* Higgsfield CLI skills. Inspect actual installed version and capabilities. No competing MCP wrapper, duplicate creative skill stack or guessed flags.
3. Resolve each `@AVELNA_*` alias from a private read-backed provider registry. Check category, image provenance, current Element status and founder-specific approval scope.
4. Never use `@AVELNA_StepWoman_01`; it is deprecated but still exists in provider library. If its source is archived, that does not remove its Element.
5. Do not assume that the connected ChatGPT MCP placeholder syntax `<<<UUID>>>` automatically works in Higgsfield CLI. Use only discovered CLI commands/roles.
6. Keep all source supplier photos, private IDs, source hashes, account scope and runtime grants outside the public repo. Real SKU/rights/water-effect tests are not yet approved for commercial use.
7. For each signed shot packet, quote cost, check real budget authorization, submit at most one video job, read back status/charge, inspect actual frames and report results. On rejected/unknown provider result do not submit a blind paid retry.
8. Reject changed bathroom geometry, generic grooves, wrong foot/character anatomy, flooded floor, fake instant-drying footage or unsupported claims. Return blockers to ChatGPT and founders with exact evidence.
9. No Meta publication, supplier outreach or full Vaultwarden export as a side effect of visual work.

This skill is a *router and policy layer*. Provider-specific generation belongs to official existing Higgsfield CLI skills and only under explicit delegated authority.
